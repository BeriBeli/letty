Letty 0.2.3 fixes Linux shortcuts and local csh/tcsh directory titles, improves
CPU rendering, and reduces memory retained by multiple windows and large frames.

- Restores modified GTK shortcuts when the input method synchronously commits
  the same ASCII character. This covers `Ctrl+,` for Settings and `Ctrl+Shift+=`
  for Markdown preview zoom while preserving composition, AltGr and delayed commits.
- Uses the working directory as the default tab title for directly launched local
  csh/tcsh sessions, updating after shell output without idle polling or changes to
  shell configuration. Manual names and explicit terminal titles retain precedence;
  OSC 7 directory reporting takes over when available.
- Accelerates solid CPU fills and skips invisible fills while preserving pixel
  output, rounded edges, borders and clipping.
- Shares immutable font-source bytes across windows and lets HarfBuzz borrow a
  retained source instead of keeping another copy. Parsed font objects and window
  rendering state keep their existing ownership.
- Reclaims exceptional frame-arena capacity after two seconds of sustained low
  demand, using a one-shot recovery frame and keeping ordinary capacity warm.
- Adds opt-in memory breakdown and reproducible memory, tab-latency and raster
  measurement tools. In the recorded macOS portable-renderer experiment, median
  RSS for four windows with 19 PTYs fell from 289.9 to 209.3 MiB; a single idle
  window stayed near 86 MiB. Paired csh measurements found no material change in
  new-tab or tab-switch latency. These are local development measurements, not
  measurements of the Linux release package; see the [full report and raw data](https://github.com/BeriBeli/letty/blob/v0.2.3/docs/performance-memory-2026-10-22.md).

### Linux download

Download **`letty-0.2.3-linux-x86_64.tar.gz`** and **`SHA256SUMS`**.

```sh
sha256sum --check SHA256SUMS
tar -xzf letty-0.2.3-linux-x86_64.tar.gz
cd letty-0.2.3-linux-x86_64
sha256sum --check SHA256SUMS
./bin/letty
```

For a versioned installation, run `./tools/install-user.sh`, then launch
`~/.local/bin/letty` or select Letty from the application menu. Add `~/.local/bin`
to `PATH` to run `letty` by name. Close Letty before uninstalling with
`~/.local/share/letty/current/tools/uninstall-user.sh`. Existing
`~/.local/opt/letty` installations remain available; pass that directory explicitly
to the install, rollback or uninstall script to manage the older location.

Requires x86_64 Linux 3.10+, glibc 2.17+, GTK 3.22.30+, GLib 2.56.1+, Cairo 1.15.12+,
an X11 display and a usable shell. Keep `bin/` and `share/` together. No Zig,
Python, sudo or system-library upgrade is needed to use the runtime package.

### Validation

Publication requires the tagged source's complete Linux CI release gate with
Zig 0.17.0, baseline CPU, ReleaseSafe and VT SIMD disabled. Checks include
unit/core/VT suites, hidden UI, GTK shortcut/input ordering, local csh directory
tracking, font-source ownership and arena recovery, settings metadata, X11 redraw
and window-icon properties, configuration, startup/restore, PTY lifecycle stress
and ELF ABI compatibility. `build-info.json` identifies the exact CI evidence.

Historical benchmark records retain their original source and binary hashes.
The oldest supported kernel/library environment, installed input methods,
remote X11/VDI and target Linux performance remain separate acceptance work.
