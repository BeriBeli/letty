Letty 0.2.0 updates the terminal engine and UI toolkit, adds local document editing,
and simplifies the Linux download.

- Upgrades pinned Ghostty VT and nanoui 0.4.0 while retaining Zig 0.17.0 and the Linux baseline.
- Uses nanoui kit controls with Letty's Paper appearance across Settings, tabs, dialogs and menus.
- Adds local text and Markdown editing with explicit save, conflict handling and unsaved-change protection.
- Improves Markdown table layout, document scrolling and configurable scroll behavior.
- Keeps only the application and its runtime resources in the Linux download. Test binaries, development documents, historical screenshots and full validation records remain in the repository and CI.
- Removes the duplicate custom source asset. Use GitHub's built-in **Source code (zip)** or **Source code (tar.gz)** below; bootstrap restores pinned dependencies.

### Linux download

Download **`letty-0.2.0-linux-x86_64.tar.gz`** and **`SHA256SUMS`**.

```sh
sha256sum --check SHA256SUMS
tar -xzf letty-0.2.0-linux-x86_64.tar.gz
cd letty-0.2.0-linux-x86_64
sha256sum --check SHA256SUMS
./bin/letty
```

For a versioned user installation, run `./tools/install-user.sh`, then launch
`~/.local/opt/letty/current/bin/letty`.

Requires x86_64 Linux 3.10+, glibc 2.17+, GTK 3.22.30+, GLib 2.56.1+, Cairo 1.15.12+,
an X11 display and a usable shell. The archive includes four Maple Mono font styles,
shell integration, icons, configuration examples, installation scripts, licenses,
ABI audit, build metadata and per-file checksums. Keep its resources together.

### Validation

GitHub Actions builds the tagged source using Zig 0.17.0, baseline CPU, ReleaseSafe
and VT SIMD disabled. Publication requires the current Linux unit/core/VT suites,
hidden UI checks, GTK smoke/input checks, configuration checks, VT golden fixtures,
20 startup/restore launches, 256 lifecycle stress cycles and ELF ABI audit.
`build-info.json` links to that workflow's complete verification evidence.

The oldest supported kernel/library environment, remote X11/VDI, real IME and
target performance remain separate acceptance work.
