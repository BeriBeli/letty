# Kero UI port

The active native entry is `src/runtime/main.zig`. Its presentation is translated
from Kero 2.1.10 at `e95cbcc85be5c55dbc47630940257c9982a2a98b` into nanoui;
there is no mygo runtime. The previous application remains recovery source and
is not linked into this entry. Only leaf UI assets and bounded text shaping
utilities are reused.

## Reference and mapping

The installed `/Applications/Kero.app` reported version 2.1.10 during the
2026-10-23 desktop comparison. Its main window, Settings General/Appearance/
Terminal pages, font menu, palette, floating Find bar, Changes panel and split
zoom/restore controls were inspected directly. Original captures are retained
locally under `.cache/kero-local-comparison/`; they are not release receipts.

| Kero source | Active nanoui implementation |
| --- | --- |
| `theme.go`: palettes and five washes | `src/runtime/presentation.zig`, `backdrop.zig`, `src/interface_assets.zig` |
| `view.go`: sidebar, groups and sessions | `src/runtime/desktop.zig`, `ui_state.zig` |
| `panes.go`: cards, headers and direct actions | `src/runtime/desktop.zig`, `layout_actions.zig` |
| Native window controls and drag regions | `src/runtime/window_chrome.zig`, `window_guard.zig` |
| `settings_view.go`, `controls.go`: groups and popup controls | `src/runtime/preferences.zig`, `preference_schema.zig`, `settings_draft.zig` |
| Palette, Find and inline rename | `src/runtime/desktop.zig`, `presentation.zig` |
| Changes card and file headers | `src/runtime/git_view.zig` |
| Native file/Markdown workspaces and side preview | `src/document_host.zig`, `src/runtime/document/`, `document_desktop.zig` |

Kero, Framework7, Meteor, Octicons and Lucide notices are retained in the
repository and copied into preview packages. See `THIRD_PARTY_NOTICES.md`.
Deterministic washes and icon assets are regenerated by
`tools/generate-rex-backdrop.py` and `tools/render-ui-icons.py`.

## Presentation and behavior

- The sidebar defaults to 268 points, resizes between 200 and 440, and meets the
  leading card directly. Cards retain 8-point outer/split gaps, 14-point corners
  and 44-point headers. Terminal cells have a 16-point content inset; resize,
  pointer/link hit testing and IME anchoring use the same value.
- Session rows are 34 points high. Rename edits the existing row. Footer actions
  expose project/file access, side preview, session search and Settings.
- Split, zoom, restore and close are compact icon controls. Zoom retains the
  existing multi-pane ownership and restore action. Main native window controls
  remain separate from pane close actions.
- Find floats below the active pane header without changing terminal dimensions.
  The 600-point command palette has compact rows, group labels and shortcut chips.
- Settings uses a 212-point sidebar, a native owned window and grouped soft
  panels. Supported pages are General, Appearance, Terminal, Shell,
  Notifications, Keyboard and Advanced. Clipboard/input settings belong to the
  Terminal page. Finite common choices use segmented controls; fonts and themes
  use searchable popovers, size uses a compact menu and line height a slider.
  The five background tiles are Petal (`rex`), Mist, Meadow, Dusk and Plain.
- Settings preview owns a configuration candidate. Save publishes atomically;
  discard restores the committed baseline, including theme colors. Only one
  draft exists application-wide. Queued mutations carry its generation, and
  previewing a smaller history limit cannot evict history before Save.
- Settings menus edit the focused Settings surface. Popovers render outside the
  scrolling page so clipping and input ownership do not hide their controls.
- Changes uses a compact comparison selector, summary counts, inline file
  headers, syntax-colored selectable text and paired/unified layouts. The local
  backend loads one selected file patch at a time; other file headers remain
  available to select. This is a remaining interaction difference from Kero's
  multiple expanded patches. Git-only controls are hidden for SVN; property and
  conflict information remains visible.

## Verification boundaries

Current native checks use owned hidden windows, private PTYs, files and clipboard
fixtures. The desktop comparison additionally operates a dedicated
`.cache/Letty UI Recovery.app` with private configuration, leaving existing user
Letty windows and configuration separate. Fresh source-bound native/unit/core/UI
receipts are required before `tools/package-port-preview.py` accepts a preview.

Visual resemblance is not a claim of pixel parity or full Kero feature parity.
The local architecture excludes Kero's daemon, Mirror, remote shared sessions and
embedded browser. The native custom UI does not yet expose Kero's complete
accessibility tree. Real Linux X11/VDI, system IME and NFS acceptance require
separate target evidence; macOS screenshots and ABI checks do not establish them.
