# Session metadata provider contract

`native.zig` wraps `src/platform/navigation_provider.{c,h}`. It imports no nanoui, Session, config or application modules. Its `Snapshot` is a fixed, owned value: branch/hash strings and at most 32 TCP listeners, with Session ID, request generation, PID and OS birth identity.

Host integration:

1. For a live, unreaped Session root, initialize `Provider.init(session.id, session.pid)` and register `notificationFd()` with the existing native fdwatch. Reject `closing`, `eof`, `fatal` and non-null exit status before lazy initialization; do not initialize against a held, already reaped PID.
2. Merge trusted local CWD, prompt completion, focus and explicit refresh events outside draw. Bound/throttle these event requests in the host. Call `start(.{ .generation = generation, .cwd = cwd_z, .git = enabled, .ports = enabled })`. It copies the path before returning. `false` means the prior short worker has not been drained: cancel it, retain its fdwatch and launch the merged newer request after notification/drain. There is no timer, draw callback or permanent worker.
3. On fd readiness, `drain()` joins a worker which has already published its completion, drains the pipe and returns owned metadata. Accept only `snapshot.currentFor(session.id, current_generation)`, and recheck the Session/window is live. Increment/revoke generations and hide old values immediately on CWD changes, disable, close and replacement. Only `git_state == .ok` supplies Git values and only `ports_state == .ok` supplies ports. Other states are unknown/error diagnostics, never an empty clean repo or a fabricated port.
4. Disable calls `cancel()` immediately and clears cached metadata. On teardown, unregister fdwatch first, then `deinit()`: it cancels and detaches a short worker without joining on the GUI thread. A private reference lets the worker reap Git and reclaim its pipe/context afterwards. It retains no host callback, pointer, Session, allocator or CWD borrow. Notification-after-close cannot publish to a destroyed object.

The worker checks cancellation/deadline at admission, in process traversal, before each FD/socket read, and in a Git poll loop of at most 10 ms between checks. Request timeout defaults to 750 ms, with an API maximum of 1500 ms. This is an execution budget, not a hard real-time guarantee for kernel scheduling or an uninterruptible OS call. Teardown itself does not wait on either. Completed jobs are joined before reuse; retired jobs release their independent native allocation when finished.

Git uses a fixed `/usr/bin/git`, no shell, a restricted environment, `--porcelain -z --branch`, disabled fsmonitor/untracked cache and ignored submodules. Porcelain v1 syntax avoids requiring modern Git on baseline Linux. Git resolves normal repos and linked-worktree `.git` files; detached HEAD returns its real abbreviated commit. Unborn branches, nonrepo, dirty, failure, permission, timeout, cancellation and output-limit states are separate. Status filenames/stderr are temporary worker buffers and are not retained in the snapshot. A worktree modified after collection is a snapshot-age limitation, so host events trigger refresh. Submodule contents are deliberately not traversed.

Port ownership is the Session root and recursively enumerated descendants that retain its controlling TTY. macOS uses `proc_listchildpids`, `PROC_PIDLISTFDS` and `PROC_PIDFDSOCKETINFO`; Linux uses only `/proc/PID/task/*/children`, the owned processes' FDs and their namespace TCP/TCP6 tables, filtering exact owned socket inodes. No all-machine PID enumeration or service such as lsof/netstat is launched. Every admitted process's parent chain, TTY and OS birth are checked again; the root birth is also checked at completion and drain. Root exit/PID reuse invalidates publication. Detached daemons with a different TTY and remote services are outside this initial ownership model.

Limits: 256 owned PIDs, 256 threads per PID while discovering children, 2048 FDs per process, 8192 FDs per job, 32 retained listeners, 4095-byte CWD, 64 KiB Git output, 8 KiB Git stderr, 256 KiB per Linux socket table. Reaching traversal/FD/table limits yields unknown/limit rather than falsely complete data. More than 32 valid listeners retains the sorted bounded list with `partial=true`. Permission failures and kernels lacking the proc children interface return unknown/unavailable. Linux code uses Linux 3.10/glibc 2.17 available interfaces; no statx or pidfd.

Leaf checks:

- `zig test src/navigation/providers/native.zig` verifies owned decoding and generation/state validation (2 checks).
- Compile/run `tests/navigation/provider_native.c` with pthread. It creates only temporary repos and its own root/descendant/sibling loopback-listener processes (24 checks). It exercises clean/dirty/worktree/detached/nonrepo, timeout, cancel, failure, output bounds, birth mismatch, source exit, 20 retirement cycles and FD recovery. Its private executable requires a sandbox exception for loopback binding in this host environment.
- macOS native run passed; strict Linux 3.10/glibc 2.17 baseline C cross-compilation passed. Target Linux/procfs permission/display/runtime remain pending; the cross-compile is not runtime evidence.

Darwin child-list units were verified against [Apple's libproc implementation](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.c): `proc_listchildpids` returns PID count, while `proc_pidinfo` FD results are byte counts.
